### 5. ManifestList（清单列表）

`ManifestList`（也称为 Fat Manifest 或 Image Index）是多架构镜像的集合。

```go
// 位置: internal/registry/types.go
type ManifestList struct {
    SchemaVersion int                  `json:"schemaVersion"` // 固定为 2
    MediaType     string               `json:"mediaType"`     // 清单列表的媒体类型
    Manifests     []ManifestDescriptor `json:"manifests"`     // 各平台 manifest 列表
}
```

**支持的媒体类型**:

- `application/vnd.docker.distribution.manifest.list.v2+json` (Docker Manifest List)
- `application/vnd.oci.image.index.v1+json` (OCI Image Index)

**示例**:

## 错误处理结构

### ErrorResponse（错误响应）

虽然没有显式定义结构体，但我们的错误响应遵循 Docker Registry API 标准格式：

```json
{
    "errors": [
        {
            "code": "BLOB_UNKNOWN",
            "message": "blob unknown to registry",
            "detail": "sha256:abc123..."
        }
    ]
}
```

**常见错误代码**:

- `BLOB_UNKNOWN`: Blob 不存在
- `MANIFEST_UNKNOWN`: Manifest 不存在
- `BLOB_UPLOAD_UNKNOWN`: 上传会话不存在
- `DIGEST_INVALID`: Digest 不匹配
- `MANIFEST_INVALID`: Manifest 格式错误

## 数据流转关系

### 1. 镜像推送流程中的数据结构

```
1. 客户端上传各个 Layer Blob (通过分片上传)
   └── 存储为内容寻址文件: blobs/sha256/xx/xxx...

2. 客户端上传 Config Blob
   └── 存储为内容寻址文件: blobs/sha256/xx/xxx...

3. 客户端上传 Manifest (引用上述 Blob 的 digest)
   └── 存储到: repositories/{repo}/_manifests/revisions/sha256/xxx...
   └── 创建标签映射: repositories/{repo}/_manifests/tags/{tag}/
```

### 2. 多架构镜像的数据结构层次

```
ManifestList (Fat Manifest)
├── ManifestDescriptor (amd64)
│   └── Manifest
│       ├── Config Descriptor → Config Blob
│       └── Layer Descriptors → Layer Blobs
└── ManifestDescriptor (arm64)
    └── Manifest
        ├── Config Descriptor → Config Blob
        └── Layer Descriptors → Layer Blobs
```

## 内容寻址存储

### Digest 格式

所有 digest 都使用 SHA256 算法，格式为：

```
sha256:0123456789abcdef...
```

### 存储路径映射

- **Blob 存储**: `blobs/sha256/{digest[0:2]}/{digest[2:]}`
- **Manifest 存储**: `repositories/{repo}/_manifests/revisions/sha256/{digest[7:]}`
- **标签映射**: `repositories/{repo}/_manifests/tags/{tag}/current/link`

### 去重机制

由于使用内容寻址存储，相同内容的 Blob 自动去重：

- 相同的 layer 在不同镜像间共享存储空间
- 相同的 config 文件只存储一份
- 通过 digest 确保内容完整性

## JSON 序列化注意事项

### omitempty 标签

许多字段使用 `omitempty` 标签，表示：

- 字段为零值时，JSON 序列化时会省略该字段
- 保持与官方规范的兼容性
- 减少不必要的数据传输

### 字段顺序

虽然 JSON 字段顺序不影响解析，但我们的结构体字段顺序遵循：

1. 必需字段在前
2. 按逻辑重要性排序
3. 可选字段在后

这种数据结构设计确保了与 Docker Registry API v2 和 OCI 规范的完全兼容性，同时保持代码的清晰性和可维护性。
