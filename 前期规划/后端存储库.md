### 库函数学习

通过 Go 语言的 `os` 和 `path/filepath` 等标准库，你可以轻松地创建、读取和操作这些文件和目录，从而实现整个 Registry 的存储逻辑。

### 文件系统存储的组织结构

为了有效管理不同仓库的镜像，你需要设计一个清晰的目录结构。一个典型的、符合 Docker Registry 逻辑的存储布局如下：

```
storage_root/
├── docker/
│   └── registry/
│       └── v2/
│           ├── repositories/
│           │   ├── <仓库名>/
│           │   │   ├── _manifests/
│           │   │   │   └── tags/
│           │   │   │       ├── <标签名>/
│           │   │   │       │   └── current/
│           │   │   │       │       └── link
│           │   │   │       └── sha256/
│           │   │   │           └── <manifest-digest>
│           │   │   └── _uploads/
│           │   │       └── <uuid>/
│           │   └── <仓库名>/...
│           └── blobs/
│               └── sha256/
│                   ├── <blob-digest>/
│                   │   └── data
│                   ├── <blob-digest>/...
```

* **`repositories/`** ：存放所有镜像仓库的元数据。
* **`<仓库名>/`** ：每个子目录代表一个独立的镜像仓库。
* **`_manifests/`** ：存放该仓库下的所有 Manifest 文件。
* **`_uploads/`** ：存放正在进行分片上传的临时数据。每个上传会话都有一个唯一的 `uuid` 目录。
* **`blobs/`** ：存放所有镜像层文件（Blob）。它们通常通过 SHA256 摘要来命名和组织，以确保全局唯一性。
